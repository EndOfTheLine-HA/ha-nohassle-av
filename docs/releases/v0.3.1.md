# v0.3.1: fix the matrix showing unavailable after a route change

Changing an input from Home Assistant switched the matrix correctly, but the
selectors then showed **unavailable** and fell back to the wrong input.

## Cause

The matrix closes its connection after every reply without saying so. Home
Assistant reuses connections, so the status request sent right after a route
command often went down a connection the matrix had already closed and failed
with "Server disconnected". Because the matrix reports a routing change only once,
that missed report was never seen, and the selector kept showing the old input.

## Changes

- A request that hits a connection the matrix already closed is retried once on a
  fresh connection. Other errors are not retried.
- After you pick an input, Home Assistant now polls a few times over about a
  second and a half until the matrix reports the new routes, instead of once.
- The README and AUDIT describe how the matrix reports routing, including that the
  selectors show Unknown after a Home Assistant restart until the next change.

## Upgrading

Update No Hassle AV in HACS and restart Home Assistant. No configuration changes.
If HACS says `No manifest.json file found`, reload HACS and try again.
